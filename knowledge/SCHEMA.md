# База знаний Пульта

Все пояснения Пульта живут здесь, в JSON. Код только читает эти файлы и применяет их к любому проекту.
Нет ни одного правила под конкретный проект: если пояснение нужно, оно добавляется сюда и работает везде.

Проверка: `node knowledge/validate.mjs` - печатает ошибки или «ok».

## Правила текста

- Русский язык, простые слова, короткие предложения. Пишем для новичка, который видит это впервые.
- Только тире «-». Длинные (U+2014) и средние (U+2013) тире запрещены, проверялка их ловит.
- Без воды и рекламы: никаких «мощный», «современный», «давайте разберёмся», «важно отметить», «стоит отметить», «является».
- Каждая фраза несёт факт. Если фразу можно выкинуть без потери смысла - выкинуть.
- Ни слова про конкретные проекты. Примеры общие: `my-app`, `api`, `web`.

## Файлы

| Файл | Что внутри |
|---|---|
| `effects.json` | что команда затрагивает: читает, пишет файлы, удаляет, сеть... |
| `stages.json` | этапы разработки и слова, по которым скрипт относится к этапу |
| `stacks.json` | как по зависимостям и файлам понять технологии проекта |
| `docs.json` | что за документ README, CHANGELOG и т.п. |
| `ui.json` | тексты подсказок интерфейса |
| `glossary.json` | общие термины (терминал, порт, процесс...) для подсказок в режиме обучения |
| `icons.json` | значки для уроков: SVG-путь в квадрате 24×24 |
| `tools/*.json` | программы и их команды: что делают, ключи, что происходит внутри |
| `topics/*.json` | уроки вкладки «Документация» |

## tools/*.json

```json
{
  "tools": [
    {
      "id": "vitest",
      "name": "Vitest",
      "topic": "testing",
      "bins": ["vitest"],
      "about": "Программа, которая запускает тесты в проектах на JavaScript и TypeScript.",
      "how": ["Ищет файлы с тестами: *.test.ts, *.spec.ts", "Запускает каждый тест", "Печатает, сколько прошло и сколько упало"],
      "default": { "say": "Запускает тесты", "fx": ["read"] },
      "sub": [
        { "match": "^watch\\b", "part": "режим наблюдения", "say": "Запускает тесты и повторяет их при каждой правке", "fx": ["read"], "long": true }
      ],
      "flags": [
        { "flag": "--watch", "alias": ["-w"], "text": "Следить за файлами и повторять тесты", "say": "и повторяет их при каждой правке", "long": true },
        { "flag": "--coverage", "text": "Посчитать, какая часть кода проверена тестами", "say": "и считает покрытие кода" }
      ],
      "help": "--help"
    }
  ]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | уникальный id, латиница |
| `name` | да | как программа называется |
| `topic` | да | id урока из `topics/` (список ниже) |
| `bins` | да | как команда начинается: `["vitest"]`, `["docker compose", "docker-compose"]`. Сравнивается без учёта регистра, по словам. Побеждает самое длинное совпадение |
| `about` | да | одна фраза: что это за программа |
| `how` | нет | 2-5 шагов «что происходит внутри» для режима обучения |
| `default` | да | что команда делает, если ни один `sub` не подошёл |
| `sub` | нет | подкоманды. `match` - регулярное выражение (строка JS) по тексту после `bins`. Первое совпадение побеждает и заменяет поля `default` |
| `flags` | нет | ключи. Если ключ есть в команде: `say` дописывается к описанию, `fx` добавляются, `fxRemove` убираются, `long`/`danger` переопределяют. `text` - пояснение ключа, обязательно |
| `help` | нет | как спросить у программы её справку (`"--help"`), `null` - если нельзя |
| `runsFile` | нет | `true` у интерпретаторов (node, python, bash...): Пульт найдёт файл в команде и прочитает его шапку |

Поля описания (`default`, элементы `sub`):

| Поле | Смысл |
|---|---|
| `say` | что делает, одна фраза с большой буквы, без точки в конце |
| `part` | короткая подпись подкоманды для разбора команды по частям |
| `fx` | эффекты из `effects.json` |
| `long` | `true`, если процесс работает, пока его не остановят (сервер, наблюдение) |
| `url` | `true`, если открывает локальный адрес вида localhost |
| `danger` | `true`, если последствия видны снаружи или необратимы |

## topics/*.json

```json
{
  "id": "docker",
  "title": "Docker",
  "color": "#2496ed",
  "icon": "box",
  "level": "основы",
  "summary": "Docker запускает программу в коробке, где уже лежит всё нужное.",
  "detect": { "files": ["Dockerfile", "docker-compose.yml"], "deps": [], "bins": ["docker"], "stacks": ["Docker"] },
  "related": ["docker-compose", "wsl"],
  "sections": [ ... ]
}
```

`detect` - когда урок показывается проекту: есть файл из `files` (имя в корне или путь `.github/workflows`), зависимость из `deps` (package.json, *.csproj, Cargo.toml, pyproject), команда из `bins` в скриптах, метка из `stacks`. `"always": true` - урок нужен любому проекту (терминал, git).

Секции (`type`):

| type | Поля | Как выглядит |
|---|---|---|
| `idea` | `title`, `text`, `analogy` | крупный вводный текст и рамка «как в жизни» |
| `diagram` | `title`, `nodes: [{id, label, note, icon}]`, `edges: [[from, to, подпись]]`, `caption` | схема из блоков и стрелок, слева направо |
| `terms` | `title`, `items: [{term, text, forms}]` | карточки терминов; `forms` - формы слова для подсказок в тексте |
| `steps` | `title`, `items: [строка]` | нумерованные шаги |
| `anatomy` | `title`, `parts: [{text, note}]` | команда, разобранная по цветным частям |
| `example` | `title`, `code`, `note`, `output` | пример команды или файла и что он выведет |
| `compare` | `title`, `cols: [..]`, `rows: [[..]]` | таблица сравнения |
| `chart` | `title`, `unit`, `items: [{label, value, note}]`, `note` | столбчатый график |
| `mistakes` | `title`, `items: [{problem, fix}]` | частые ошибки и как чинить |
| `cheatsheet` | `title`, `items: [{cmd, text}]` | шпаргалка команд |
| `quiz` | `title`, `items: [{q, options: [..], answer: номер с 0, why}]` | вопросы с проверкой |
| `project` | `title` | заполняет Пульт: скрипты этого проекта, где используется технология |
