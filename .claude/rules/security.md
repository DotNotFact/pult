# Безопасность Пульта

Пульт открывает ЧУЖИЕ папки: скачанный репозиторий, архив коллеги. Всё в
них - данные, которым нельзя доверять: имена файлов, `package.json`,
`.git/config`, шапки скриптов. Каждая защита ниже закрывает конкретный
путь, по которому открытие папки превращается в запуск чужого кода или
утечку токена. Снять защиту - решение владельца и ADR, а не правка.

| Защита | Где | От чего |
|---|---|---|
| Запуск без оболочки: программа и аргументы списком | `core/src/runner.rs` | имя файла или аргумент вида `a & del ...` не станет второй командой (`docs/adr/0003-no-shell.md`) |
| `.cmd`/`.bat` ищутся только из `PATHEXT` в пределах `.com .exe .bat .cmd` | `runner::which` | подмена программы файлом с чужим расширением |
| git всегда с `-c core.fsmonitor=false`, `log.showSignature=false`, `protocol.allow=never`, `safe.bareRepository=explicit`, `submodule.recurse=false`, `--no-pager` | `core/src/git.rs`, `SAFE` | `core.fsmonitor` в чужом `.git/config` запускает любую программу при `git status` |
| До первого вызова git Пульт сам читает `.git/config` (и `config.worktree`, общий каталог). `filter.*`, `gpg.*`, `include*`, `core.hooksPath`, `core.sshCommand`, `core.pager`, `diff.*.textconv` и похожие - репозиторий «не доверен»: git не запускается, пока человек не нажмёт «Доверять». Доверие - в `Config.trusted_repos`, не в настройках | `git::locate`, `parse_config`, `store::trust_repo` | clean-фильтр и `gpg.program` выполняются при `git status`/`git log` без единого клика |
| Сетевой путь в gitdir, alternates, любом значении config или в цели ссылки - отказ без права доверить | `git.rs` | git сам сходил бы на `\\host\share` и отдал хэш NTLM |
| «Спросить у программы»: справка (`--help`, у подкоманды - по шаблону `help` из базы) идёт из папки данных Пульта; подкомандой считается только простое слово, которое база узнала сразу за программой, - не файл и не путь; у интерпретаторов (`runsFile`) справка только общая; программа из проекта (`node_modules/.bin`, путь внутри проекта) запускается только после подтверждения с полным путём | `core/src/helpcmd.rs`, `askHelp` в `ui/app.js` | файл в репозитории под видом справки |
| Адрес remote проверяется: GitHub - ровно `owner/repo`, GitLab - группы из `[A-Za-z0-9_.-]`; `gh`/`glab` получают хост явно и работают из папки данных | `git::valid_slug`, `ci.rs` | `github.com/evil.example/o/r` увёл бы запрос и токен на чужой хост |
| Ссылки и junction при обходе папок пропускаются; путь для `open` проверяется после разрешения ссылок | `util::ls`, `util::resolve_inside` | ссылка из репозитория на `\\host\share` или за пределы проекта |
| База знаний ищется только рядом с exe (и в корне репозитория для сборки из исходников) | `paths::home` | подложенная `Downloads\knowledge\` заменила бы правила открытия файлов |
| Остановка гасит дерево через Job Object | `runner.rs` | осиротевшие потомки после «Стоп» |
| CI-запросы только к доверенным хостам: `heuristics.ciHosts` плюс `ciHosts` из настроек | `core/src/ci.rs`, `store::trusted_hosts` | адрес remote из чужого `.git/config` получил бы токен `glab`/`gh` |
| CI только по запросу, без фонового опроса | `ci.rs` | лишние запросы к API и лимиты аккаунта |
| Документ открывается программой по умолчанию только с расширением из `heuristics.docExtensions`, иначе - в редакторе | `app/src/main.rs`, `open` | `readme.js` или `license.bat` запустились бы по двойному щелчку |
| Пути для `open` только внутри открытого проекта; «Проводник» открывает только папки, файл - показывает выделенным | `app/src/main.rs`, `target` | `../../` за пределы проекта; `explorer.exe x.bat` запустил бы файл |
| Ссылки наружу только `http`/`https` без кавычек и переводов строк | `app/src/main.rs`, `open` | `file:`, `javascript:` и склейка аргументов |
| Сетевые (UNC) пути не разбираются и не открываются | `util::is_unc`, `scan.rs`, `explain.rs` | обращение к `\\host\share` отдаёт хэш NTLM чужому серверу |
| `.env` не читается: проверяется только наличие файла | `scan.rs` | секреты в памяти, кэше и журнале |
| Нет сервера и порта: окно говорит с ядром через IPC Tauri | `app/` | доступ к ядру с чужой страницы или из сети |
| CSP: только свои скрипты, `connect-src ipc:` | `app/tauri.conf.json` | XSS из вывода программы или имени файла |
| Права окна - минимум (`core:default`, диалог открытия, уведомления, состояние окна) | `app/capabilities/default.json` | лишние API Tauri в WebView |
| Всё чужое в HTML через `esc()` | `ui/app.js`, `ui/learn.js` | XSS из имени скрипта, ветки, журнала CI |
| Порт отладки WebView2 только в debug-сборке и по `PULT_DEBUG_PORT` | `app/src/main.rs` | CDP в релизе дал бы любому процессу управление окном |

## Как проверять

- Новый `Command::new` - почему не через `runner`? `cmd /c`, `sh -c`,
  `powershell -Command` со строкой - отказ.
- Новый вызов git - через `git.rs`?
- Новый `innerHTML` - каждая переменная через `esc()`?
- Новое чтение файла проекта - не `.env`, не UNC, не за пределами корня?
- Новый сетевой запрос - хост из доверенных?

Агент `security-reviewer` проходит этот список на каждом диффе, который
трогает `runner`, `git`, `ci`, `open`, `ui/` или `tauri.conf.json`.
