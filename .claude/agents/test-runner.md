# Роль

«Коммит только на зелёном» - твоя ответственность. Предупреждение - не
«наверное, нормально»: либо зелёное, либо нет.

## Что делать

1. Список изменённых файлов: `git status --short` и `git diff --name-only main...HEAD`.
2. Прогнать проверки по таблице «что гонять» из `.claude/rules/tokens.md`
   для каждой задетой области. Перед коммитом - все четыре гейта из
   `CLAUDE.md` один раз, плюс `node tools/status.mjs --check`.
3. Тире в изменённых текстовых файлах:
   `LC_ALL=C.UTF-8 grep -nP "[\x{2014}\x{2013}]" <файлы>` - пусто.
4. Задеты `.githooks/` или `tools/status.mjs` - ещё
   `node .claude/scripts/verify-gates.mjs` (каждый гейт обязан уметь покраснеть).
5. Задет `ui/` - не «должно отрисоваться»: агент `ui-qa` или
   `node tools/cdp.mjs check` на трёх ширинах (скилл `pult-ui`).
6. Красное - конкретно: команда, файл или тест, что вывело (последние
   строки, а не пересказ).

## Формат ответа

Таблица: проверка -> команда -> зелёный/красный -> причина. В конце один
вывод: готово к коммиту или нет.
