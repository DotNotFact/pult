# Как помочь Пульту

Спасибо, что заглянули. Помочь можно тремя способами, и первый самый ценный.

## 1. Научить Пульт новой программе

Всё, что Пульт рассказывает о командах, лежит в `knowledge/` в JSON. Код только
читает эти файлы. Если Пульт не знает вашу программу или объясняет её плохо,
правка почти всегда нужна в JSON, а не в Rust.

| Что добавить | Куда |
|---|---|
| Программу, её подкоманды и ключи | `knowledge/tools/<группа>.json` |
| Урок по технологии | `knowledge/topics/<id>.json` |
| Термин для подсказки при наведении | `knowledge/glossary.json` |
| Новый вид файла проекта (`Taskfile`, `pyproject` и т. п.) | `knowledge/manifests.json` |

Формат каждого файла описан в [`knowledge/SCHEMA.md`](knowledge/SCHEMA.md).
После правки:

```bash
node knowledge/validate.mjs
```

Проверка смотрит схему, ссылки между файлами, регулярные выражения и текст.

### Каким должен быть текст

- Простые слова. Читатель может впервые видеть терминал.
- Сначала что делает, потом зачем. Без вступлений вроде «это мощный инструмент».
- Только обычный дефис `-`. Длинные тире проверка не пропустит.
- Пример лучше абзаца объяснений.

## 2. Сообщить об ошибке

[Откройте issue](https://github.com/DotNotFact/pult/issues/new/choose). Больше всего
помогают версия Пульта, что вы открыли и что увидели. Если ошибка в разборе
проекта, приложите кусок `package.json`, `Makefile` или другого файла, на котором
она случилась.

Уязвимости не публикуйте в issue, порядок описан в [SECURITY.md](SECURITY.md).

## 3. Правка кода

Нужны Rust stable, Node 22 и Windows 10 или 11 с WebView2.

```bash
cargo build -p pult-app -p pult-cli
cargo run -p pult-app -- путь/к/проекту
cargo run -p pult-cli -- -C путь/к/проекту info
```

Перед pull request прогоните то же, что прогонит CI:

```bash
node knowledge/validate.mjs
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Устройство проекта описано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), принятые
решения записаны в [docs/decisions.md](docs/decisions.md) и [docs/adr/](docs/adr/).
Прежде чем предлагать большую переделку, загляните туда: возможно, этот путь уже
пробовали.

Несколько правил, которые проверяют на ревью:

- **Ничего под конкретный проект.** Правило, которое работает только для
  одного репозитория, не принимается. Оно должно работать для любого проекта.
- **Процессы запускаются без оболочки**, списком аргументов, через функции
  `core/src/runner.rs`.
- **Тексты интерфейса берутся из `knowledge/ui.json`**, в `ui/app.js` их не пишут.
- **Всё, что пришло из проекта, выводится через `esc()`.**

## Pull request

- Одна задача, один PR. Мелкие PR проходят быстрее.
- Ветка от свежего `main`.
- Сообщение коммита: первой строкой что стало правдой («Пульт понимает Taskfile»,
  а не «правки»). Язык любой.
- Если поведение изменилось, добавьте строку в `CHANGELOG.md`, раздел `[Unreleased]`.

Присылая PR, вы соглашаетесь, что код выходит под лицензией [MIT](LICENSE).
