# База знаний (`knowledge/`)

Формат целиком - `knowledge/SCHEMA.md`. Здесь то, что ломается молча.
Почему знания в данных - `docs/adr/0002-knowledge-as-data.md`.

## Где что лежит

| Файл | Что внутри |
|---|---|
| `tools/*.json` | программы: `bins`, `about`, `how`, `default`, `sub`, `flags`, `help`, `runsFile` |
| `topics/*.json` | уроки вкладки «Документация»: `detect`, `sections` |
| `effects.json` | эффекты команды (читает, пишет, удаляет, сеть) |
| `stages.json` | этапы разработки и слова-признаки |
| `heuristics.json` | общие списки: `docExtensions`, `ciHosts` и другие |
| `manifests.json` | стандартные команды манифестов (npm, cargo, dotnet...) |
| `stacks.json`, `docs.json`, `ui.json`, `glossary.json`, `icons.json` | стек, документы корня, тексты интерфейса, термины, значки |
| `ai.json` | вкладка «ИИ»: виды деталей ИИ-части проекта, слои схемы, рассказ |

Файл в `tools/` выбирается по теме (`node.json`, `rust.json`, `docker.json`...);
новый файл заводится, только если ни один не подходит.

## Добавить программу

1. Проверить, что её нет: `grep -rn '"id": "<id>"' knowledge/tools`.
2. Дописать объект в подходящий `tools/*.json`. Обязательные поля: `id`,
   `name`, `topic` (id существующего урока), `bins`, `about`, `default`.
3. `sub[].match` - регулярное выражение в синтаксисе JS (строка), по тексту
   после `bins`. Первое совпадение побеждает. Ядро компилирует его лениво
   через fancy-regex с лимитом перебора: лишнее заглядывание назад стоит
   времени на каждом проекте.
4. Каждому ключу в `flags` - `text`. `fx` - только из `effects.json`.
5. `node knowledge/validate.mjs tools/<файл>.json`, затем прогон на
   настоящей папке (скилл `pult-kb`).

## Добавить урок

1. Новый `topics/<id>.json` по примеру соседнего.
2. id дописать в `knowledge/lessons.json` (поле `order`) на нужное место -
   оттуда порядок и список берут окно, терминал и проверка. В коде уроков нет.
3. `detect` - только общие признаки (файл, зависимость, команда, метка
   стека). Ни одного имени конкретного проекта.
4. `icon` - ключ из `icons.json`.

## Добавить вид детали ИИ-части

Один новый объект в `kinds` файла `ai.json`, кода не трогать:

1. `id`, `title`, `icon` (из `icons.json`), `layer` (из `layers`; в слое вид уже должен быть перечислен в `kinds`).
2. `format` - как читать файл из готовых: `markdown`, `script`, `permissions`, `hooks`, `hookscript`, `mcp`,
   `config`. Нужен формат, которого нет, - это правка `core/src/ai.rs` (новый разбор), а не данных.
3. `detect[]` - шаблоны от корня проекта, чья конвенция (`eco`) и как деталь загружается (`mode` из `modes` вида).
4. `parse`, `refs`, `modes` и `words` (что это, когда срабатывает, зачем, как в жизни, на что смотреть) простыми
   словами, `lesson` - id урока.
5. `node knowledge/validate.mjs`, затем `cargo run -p pult-cli -- -C <проект> ai` на настоящей папке.

Тексты про проекты - никакие: пример общий. Подробности полей - `SCHEMA.md`, раздел `ai.json`.

## Текст

Правила - `SCHEMA.md`, раздел «Правила текста». Коротко: русский, для
новичка, только «-», без воды. `validate.mjs` ловит тире и список
запрещённых слов; хук `.claude/hooks/validate-kb.mjs` гоняет его после
каждой правки файла в `knowledge/`.

## Проверка

```bash
node knowledge/validate.mjs                    # всё
node knowledge/validate.mjs tools/rust.json    # один файл (ссылки сверяются со всеми)
```

Вывод `ok · программ: N ...` - зелёное. Любая строка с ошибкой - красное.
Ядро читает базу с диска без пересборки; кнопка «Перечитать» в окне
(`kb_reload`) подхватывает правку сразу.
