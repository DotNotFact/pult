# Фича в два шага

Шаги не смешиваются в одном ответе.

## Шаг 1 - спецификация и план, без правок

Роль - агент `architect`. Задача владельца читается дословно, код - в
границах задачи. Ни один файл не правится до явного «выполняй».

Каждая подзадача в формате `.claude/rules/verification.md`:

- **Критерии приёмки - имена тестов** (`core/tests/<модуль>.rs`), для вида -
  снимок окна на 420, 900, 1320 в обеих темах.
- **Данные** - настоящая папка проекта, на которой это видно.
- **Границы** - какие файлы можно трогать. Знание (текст, признак, команда
  манифеста) - в `knowledge/*.json`, а не в коде.
- **Definition of Done** - у каждого пункта способ проверки (гейт, тест,
  `tools/cdp.mjs check`, прогон `core/examples/scan.rs`). Пункт без способа
  проверки в план не входит.
- **Документы** - что правится по правилу ноль (`CLAUDE.md`).

Вопросы владельцу - одной пачкой (`docs/contract.md`), после `grep` по
`docs/decisions.md`. Отметить независимые подзадачи (параллель, скилл
`pult-flow`) и порядок зависимых. Показать план и ждать.

## Шаг 2 - выполнение подтверждённой подзадачи

- Definition of Done дословно; тест до кода там, где у правки есть контракт.
- Перед «готово» - агент `test-runner` по затронутой области. Красное - не готово.
- Правка окна - снимки и `node tools/cdp.mjs check` (скилл `pult-ui`).
- Вышло за границы плана - остановиться и сказать, а не «заодно поправить».
- Ревью - агент `code-reviewer`; запуск, пути, git, CI, `ui/` - ещё
  `security-reviewer`. Коммит - только после ревью.
- В конце - дифф и решения, которые не видны из кода: не «что сделано», а
  «почему так».
