# База знаний Пульта

Все пояснения Пульта живут здесь, в JSON. Код только читает эти файлы и применяет их к любому проекту.
Нет ни одного правила под конкретный проект: если пояснение нужно, оно добавляется сюда и работает везде.

Проверка: `node knowledge/validate.mjs` - печатает ошибки или «ok».

## Правила текста

- Русский язык, простые слова, короткие предложения. Пишем для новичка, который видит это впервые.
- Только тире «-». Длинные (U+2014) и средние (U+2013) тире запрещены, проверялка их ловит.
- Без воды и рекламы: никаких «мощный», «современный», «давайте разберёмся», «важно отметить», «стоит отметить», «является».
- Каждая фраза несёт факт. Если фразу можно выкинуть без потери смысла - выкинуть.
- Ни слова про конкретные проекты. Примеры общие: `my-app`, `api`, `web`.

## Файлы

| Файл | Что внутри |
|---|---|
| `effects.json` | что команда затрагивает: читает, пишет файлы, удаляет, сеть... |
| `stages.json` | этапы разработки и слова, по которым скрипт относится к этапу |
| `stacks.json` | как по зависимостям и файлам понять технологии проекта |
| `docs.json` | что за документ README, CHANGELOG и т.п. |
| `ui.json` | тексты подсказок интерфейса |
| `scenarios.json` | готовые сценарии вкладки «Сценарии»: `templates[]` с `id`, `name`, `why` и `steps[]`; шаг находит скрипт по `stage` (id из stages.json) и `name` (регулярное выражение JS без учёта регистра), `optional` - шаг можно не найти |
| `ai.json` | вкладка «ИИ»: виды деталей ИИ-части проекта (инструкции, правила, агенты, навыки, хуки, MCP...), слои схемы, рассказ о том, как они работают вместе; подробности ниже |
| `glossary.json` | общие термины (терминал, порт, процесс...) для подсказок в режиме обучения |
| `icons.json` | значки для уроков: SVG-путь в квадрате 24×24 |
| `tools/*.json` | программы и их команды: что делают, ключи, что происходит внутри |
| `topics/*.json` | уроки вкладки «Документация» |

## tools/*.json

```json
{
  "tools": [
    {
      "id": "vitest",
      "name": "Vitest",
      "topic": "testing",
      "bins": ["vitest"],
      "about": "Программа, которая запускает тесты в проектах на JavaScript и TypeScript.",
      "how": ["Ищет файлы с тестами: *.test.ts, *.spec.ts", "Запускает каждый тест", "Печатает, сколько прошло и сколько упало"],
      "default": { "say": "Запускает тесты", "fx": ["read"] },
      "sub": [
        { "match": "^watch\\b", "part": "режим наблюдения", "say": "Запускает тесты и повторяет их при каждой правке", "fx": ["read"], "long": true }
      ],
      "flags": [
        { "flag": "--watch", "alias": ["-w"], "text": "Следить за файлами и повторять тесты", "say": "и повторяет их при каждой правке", "long": true },
        { "flag": "--coverage", "text": "Посчитать, какая часть кода проверена тестами", "say": "и считает покрытие кода" }
      ],
      "help": "--help"
    }
  ]
}
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `id` | да | уникальный id, латиница |
| `name` | да | как программа называется |
| `topic` | да | id урока из `topics/` (список ниже) |
| `bins` | да | как команда начинается: `["vitest"]`, `["docker compose", "docker-compose"]`. Сравнивается без учёта регистра, по словам. Побеждает самое длинное совпадение |
| `about` | да | одна фраза: что это за программа |
| `how` | нет | 2-5 шагов «что происходит внутри» для режима обучения |
| `default` | да | что команда делает, если ни один `sub` не подошёл |
| `sub` | нет | подкоманды. `match` - регулярное выражение (строка JS) по тексту после `bins`. Первое совпадение побеждает и заменяет поля `default` |
| `flags` | нет | ключи. Если ключ есть в команде: `say` дописывается к описанию, `fx` добавляются, `fxRemove` убираются, `long`/`danger` переопределяют. `text` - пояснение ключа, обязательно |
| `help` | нет | как спросить у программы её справку, `null` - если нельзя. Ключ (`"--help"`) значит: сначала справка подкоманды из команды скрипта (`cargo check --help`), если она не дала ключей - общая (`cargo --help`); у программ с `runsFile` - только общая. Список шаблонов задаёт порядок сам: `["{bin} {sub} -h", "{bin} -h"]`, `["{bin} help {sub}", "{bin} help"]`. `{bin}` - слова программы из `bins`, `{sub}` - подкоманда (первое слово правила `sub`, если оно стоит сразу за программой и это простое слово, не файл и не ключ); шаблон с `{sub}` без подкоманды пропускается |
| `runsFile` | нет | `true` у интерпретаторов (node, python, bash...): Пульт найдёт файл в команде и прочитает его шапку |

Поля описания (`default`, элементы `sub`):

| Поле | Смысл |
|---|---|
| `say` | что делает, одна фраза с большой буквы, без точки в конце |
| `part` | короткая подпись подкоманды для разбора команды по частям |
| `fx` | эффекты из `effects.json` |
| `long` | `true`, если процесс работает, пока его не остановят (сервер, наблюдение) |
| `url` | `true`, если открывает локальный адрес вида localhost |
| `danger` | `true`, если последствия видны снаружи или необратимы |

## topics/*.json

```json
{
  "id": "docker",
  "title": "Docker",
  "color": "#2496ed",
  "icon": "box",
  "level": "основы",
  "summary": "Docker запускает программу в коробке, где уже лежит всё нужное.",
  "detect": { "files": ["Dockerfile", "docker-compose.yml"], "deps": [], "bins": ["docker"], "stacks": ["Docker"] },
  "related": ["docker-compose", "wsl"],
  "sections": [ ... ]
}
```

`detect` - когда урок показывается проекту: есть файл из `files` (имя в корне или путь `.github/workflows`), зависимость из `deps` (package.json, *.csproj, Cargo.toml, pyproject), команда из `bins` в скриптах, метка из `stacks`. `"always": true` - урок нужен любому проекту (терминал, git).

Секции (`type`):

| type | Поля | Как выглядит |
|---|---|---|
| `idea` | `title`, `text`, `analogy` | крупный вводный текст и рамка «как в жизни» |
| `diagram` | `title`, `nodes: [{id, label, note, icon}]`, `edges: [[from, to, подпись]]`, `caption` | схема из блоков и стрелок. Пульт сам кладёт её слева направо или сверху вниз - как влезет в натуральную величину. Блоки перечисляйте по порядку событий: стрелка, замыкающая цикл, рисуется дугой |
| `terms` | `title`, `items: [{term, text, forms}]` | карточки терминов; `forms` - формы слова для подсказок в тексте |
| `steps` | `title`, `items: [строка]` | нумерованные шаги |
| `anatomy` | `title`, `parts: [{text, note}]` | команда, разобранная по цветным частям |
| `example` | `title`, `label`, `code`, `note`, `output`, `outputLabel` | пример команды или файла и что он выведет; `label` - подпись над кодом (`C#`, `Dockerfile`), `outputLabel` - над выводом вместо «Что выведет» |
| `codepair` | `title`, `left: {label, code}`, `right: {label, code}`, `note` | два кода рядом: C# и IL, до и после, Dockerfile и слои. В узком окне - один под другим |
| `compare` | `title`, `cols: [..]`, `rows: [[..]]` | таблица сравнения |
| `chart` | `title`, `unit`, `items: [{label, value, note}]`, `note` | столбчатый график |
| `mistakes` | `title`, `items: [{problem, fix}]` | частые ошибки и как чинить |
| `rules` | `title`, `items: [{kind, title, text}]` | как правильно: `kind` - `do` (делайте), `dont` (не делайте), `when` (когда применять), `tip` (совет) |
| `practice` | `title`, `task`, `steps: [..]`, `check`, `hint`, `solution` | «Попробуйте сами»: задание, шаги, как понять, что получилось, подсказка и решение под спойлером |
| `cheatsheet` | `title`, `items: [{cmd, text, group}]` | шпаргалка команд; `group` - подзаголовок, ставится у первой команды группы |
| `quiz` | `title`, `items: [{q, options: [..], answer: номер с 0, why}]` | вопросы с проверкой |
| `project` | `title` | заполняет Пульт: скрипты этого проекта, где используется технология |

## Список уроков

Список и порядок - в `lessons.json` (поле `order`). Его читают окно, терминал и `validate.mjs`. Новый урок - файл `topics/<id>.json` и строка в `lessons.json`, больше ничего.

## ai.json

Вкладка «ИИ» и `pult ai` показывают, что в проекте настроено для работы с ИИ-агентом. Код (`core/src/ai.rs`) умеет читать несколько форматов файлов; какой файл какой деталью считается и что о ней сказать, решает этот файл. Новый вид детали - одна запись в `kinds`, правка кода не нужна.

```json
{
  "lesson": "ai-dev",
  "limits": { "fileBytes": 262144, "walkFiles": 80000, "summary": 240 },
  "walkSkip": [".claude/worktrees"],
  "markers": [".claude", "CLAUDE.md"],
  "secrets": { "key": "...", "value": "...", "inline": "...", "userinfo": "..." },
  "facts": { "allow": "разрешено" },
  "kinds": [{
    "id": "rules", "title": "Правила", "icon": "list", "layer": "context", "format": "markdown",
    "detect": [{ "glob": ".claude/rules/**/*.md", "eco": "Claude Code", "mode": "always", "modes": [{ "key": "paths", "mode": "paths" }] }],
    "parse": { "name": [], "nameFrom": "file", "desc": ["description"], "paths": ["paths", "globs"], "tools": [], "model": [] },
    "refs": ["path", "file"],
    "modes": { "always": { "label": "всегда", "say": "..." }, "paths": { "label": "по путям", "say": "..." } },
    "words": { "what": "...", "when": "...", "why": "...", "analogy": "...", "look": "..." },
    "lesson": "ai-dev"
  }],
  "layers": [{ "id": "context", "title": "Контекст", "say": "...", "kinds": ["instructions", "rules"] }],
  "story": [{ "id": "plan", "title": "...", "say": "Его делает: {parts}.", "any": [{ "kind": "agents", "match": "(?i)plan" }] }]
}
```

| Поле | Смысл |
|---|---|
| `lesson` | id урока, на который ведут ссылки «Подробнее» (должен быть в `lessons.json`) |
| `limits` | потолки: `fileBytes` - сколько читать из файла, `walkFiles` - сколько файлов обходить для подсчёта шаблонов путей, `itemsPerKind`, `summary` и `desc` - длина краткого и полного описания (режется по границе предложения), `bodyScan` - сколько текста искать на упоминания, `hits` - примеров следа на деталь, `mentionMin` - короче этого имя не считается ссылкой |
| `walkSkip` | папки проекта, куда обход не заходит (поверх `skipDirs` из `heuristics.json`): чужие рабочие копии |
| `markers` | признаки в корне (имя или путь): есть хотя бы один - у проекта есть вкладка «ИИ» |
| `secrets` | регулярные выражения (синтаксис Rust): имена ключей, значения которых скрываются, вид значения-секрета, пара «имя=значение» в строке команды, логин:пароль в адресе |
| `facts` | подписи коротких фактов о детали (`allow`, `deny`...) |
| `ignoreFiles` | имена файлов-заглушек, которые не считаются |
| `storyMore` | «и ещё {n}» в конце списка деталей рассказа |

Вид (`kinds[]`):

| Поле | Обязательно | Смысл |
|---|---|---|
| `id`, `title`, `icon` | да | id (латиница), название блока, значок из `icons.json` |
| `layer` | да | слой схемы из `layers` |
| `format` | да | как читать файл: `markdown` (шапка YAML + текст), `script` (первый комментарий; имя файла - событие git, если оно в `events`), `permissions` (JSON настроек: разрешения, env), `hooks` (хуки из JSON настроек), `hookscript` (файл-скрипт хука), `mcp` (серверы из JSON), `config` (прочий файл настроек), `checks` (скрипты проекта этапа `check`, джобы CI и файлы по `detect`), `signals` (следы: папка, файл или совпадение строки в `scanKinds`) |
| `detect[]` | да (кроме `checks`, `signals`) | `glob` - шаблон от корня проекта; `eco` - чья это конвенция (подпись значка); `mode` - как деталь загружается, ключ из `modes`; `modes[]` - переопределение по ключу шапки (`key`, `equals`, `mode`); `format` - формат этого шаблона, если он не вида; `role` - роль детали; `private` - только числа, правил и команд не выводить |
| `parse` | да (кроме `checks`, `signals`) | `name` - ключи шапки с именем, `nameFrom` - иначе `file`, `filename`, `dir` или `path`; `desc` - ключи с описанием; `paths`, `tools`, `model` - ключи шапки с шаблонами путей, инструментами, моделью |
| `refs` | да | чем на деталь ссылаются в обратных кавычках и ссылках markdown: `path`, `file`, `name`, `tag` (имя с разделителем), `slash` (`/имя`), `script` (файл, который запускает запись хука) |
| `modes` | да | режимы загрузки: `label` (короткая подпись значка) и `say` (одно предложение) |
| `roles` | нет | роли деталей вида (`docs`): `label`, `say` |
| `words` | да | простыми словами: `what` - что это, `when` - когда срабатывает, `why` - зачем, `analogy` - как в жизни, `look` - на что смотреть |
| `lesson` | да | id урока |

Связи между деталями берутся только из данных: упоминание в обратных кавычках, ссылка markdown, `@путь`, путь к скрипту в команде хука или в тексте другого скрипта. Совпадение, которое подходит двум деталям сразу, отбрасывается. Ничего не запускается: ни хук, ни MCP-сервер, ни скрипт; `.env*` не читаются; значения env и похожие на секрет части команд заменяются на «•••».

`layers[]` - слои схемы на вкладке (`id`, `title`, `say`, `kinds`); каждый вид лежит ровно в одном слое.

`story[]` - рассказ «как это работает вместе»: шаг появляется, только если у проекта есть подходящая деталь. `any[]` - условия «или»: `kind`, необязательно `mode`, `role` и `match` (регулярное выражение по имени и описанию). В `say` можно подставить `{parts}` (до четырёх имён деталей и «и ещё N») и `{n}` (сколько деталей подошло). `always: true` - шаг есть у любого проекта с ИИ-частью.
