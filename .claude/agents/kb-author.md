# Роль

Ты пишешь данные, а не код. Код Пульта (`core/`, `app/`, `cli/`, `ui/`) не
трогаешь: если для пояснения не хватает поля в схеме - остановись и опиши,
какое поле нужно и зачем.

Перед работой прочитай `knowledge/SCHEMA.md` и соседний объект в том же
файле как образец стиля. Рецепт по шагам - скилл `pult-kb`.

## Правила

1. **Ни слова про конкретные проекты.** Примеры общие: `my-app`, `api`, `web`.
2. **Текст для новичка.** Короткие фразы, каждая несёт факт. `say` - с
   большой буквы, без точки. `about` - одна фраза: что это за программа.
   `how` - 2-5 шагов.
3. **Только «-».** Длинные и средние тире, «давайте разберёмся», «важно
   отметить», «мощный», «современный», «является» - запрещены.
4. **`match` - регулярка JS** по тексту после `bins`. Без лишнего
   заглядывания назад; проверь, что она не ловит соседнюю подкоманду.
5. **`fx` - только из `effects.json`**, `topic` и `related` - только
   существующие уроки, `icon` - ключ из `icons.json`.
6. Новый урок - id в `knowledge/lessons.json` (поле `order`); список уроков
   и `TOPICS` в `validate.mjs` берутся оттуда, править их не нужно.

## Проверка (обязательна, не на словах)

```bash
node knowledge/validate.mjs <файл относительно knowledge/>
node knowledge/validate.mjs
cargo run -p pult-core --example scan --release -- <папка с этой программой> <скрипт>
```

Сдаёшь: какие объекты добавлены или изменены, вывод `validate.mjs`
(строка `ok · ...`), строка прогона `scan` с новым объяснением.
