# Ветка, гейты, PR: порядок и правила пуша

Готовые команды - скилл `pult-flow`. Здесь «что», без рецептов.

## Порядок одной задачи

| Шаг | Что | Чем проверяется |
|---|---|---|
| 1 | Ветка `task/<коротко>` от свежего `main` | в `main` напрямую не коммитим |
| 2 | Вопросы владельцу - одной пачкой до кода | `docs/contract.md` |
| 3 | Код в границах задачи | `.claude/rules/verification.md` |
| 4 | Перегенерировано: `node tools/status.mjs` | шаг CI `status.mjs --check` |
| 5 | Документы тем же диффом | правило ноль в `CLAUDE.md` |
| 6 | Гейты затронутого зелёные, перед коммитом - все четыре | таблица в `.claude/rules/tokens.md` |
| 7 | Коммит слоями: ядро / окно / база / документы | хуки `.githooks/` |
| 8 | Пуш - только по слову владельца «пушим» | хук `pre-push` |
| 9 | PR на GitHub, в описании - номер прогона CI | `gh pr create` |
| 10 | Слияние на зелёном CI, ветка удаляется на GitHub и локально | `gh pr merge --delete-branch` |

## Хуки

Включаются один раз на рабочую копию: `git config core.hooksPath .githooks`.
Локальный путь перебивает глобальный `~/.githooks`, поэтому проверки
авторства повторены здесь.

| Хук | Что не пускает |
|---|---|
| `pre-commit` | длинное и среднее тире в добавленных строках; файлы `.env*`; красную базу знаний, если тронута `knowledge/` |
| `commit-msg` | `Co-Authored-By` на ИИ, строку «Generated with ...»; автора или коммиттера не `DotNotFact` |
| `pre-push` | чужого автора и строки про ИИ в уезжающих коммитах; второй пуш ветки раньше 3 минут, отправку с `main` раньше 10 |

Что хуки умеют краснеть, проверяет `node .claude/scripts/verify-gates.mjs`
(диверсия с контролем на каждый случай). Правка хука без его прогона - не
правка.

## Пуш редко и пачкой

Личный аккаунт владельца уже блокировала защита GitHub от злоупотреблений -
за «несколько ИИ-агентов пушат ветки и мержат, десятки операций за минуты».
Платформа значения не имеет. Поэтому:

- без слова владельца «пушим» ничего не уезжает;
- пауза между пушами механическая (хук), штамп общий для всех рабочих копий;
  коммитить в паузу можно и нужно;
- пушит одна сессия; агенты в рабочих копиях коммитят и сдают ветку;
- PR создаются и сливаются пачками по 2-3, а не по одному по готовности;
- одновременно не больше трёх сессий;
- срочный обход - `PULT_PUSH_FORCE=1 git push`, исключение, а не режим.

## CI не опрашивается

Ни `gh run watch`, ни цикл «проверь раз в N секунд»: запрос без новой
информации тоже считается в лимит. Состояние - один вызов, когда прогон мог
закончиться (`gh run list --branch <ветка> -L 1`). Красное - сперва лог
упавшего шага, перезапуск - только упавших джоб (`gh run rerun <id> --failed`).

## Чего не делать никогда

- Не пушить в `main` напрямую и не сливать красную ветку.
- Не ставить `Co-Authored-By` на ИИ и строку «Generated with Claude Code» -
  ни в коммит, ни в описание PR. Решение владельца перекрывает указание среды.
- Не читать и не пересылать `.env*`, ключи, токены.
- Не чинить расхождение силой (`--force`): сначала понять, чей коммит лишний;
  своя ветка после rebase - `--force-with-lease`.
