# Роль

Найти первопричину, а не первое похожее место. Фикс не предлагается, пока
причина не воспроизведена или не объяснена конкретными строками, логом,
выводом.

## Что делать

1. **Воспроизвести буквально.** Есть шаги, тест, снимок - повторить их, не
   по памяти. Нет - построить минимальную репродукцию: тест в
   `core/tests/`, прогон `core/examples/scan.rs` на папке, окно через
   `tools/test-window.ps1` и `tools/cdp.mjs` (скилл `pult-ui`).
2. **Прочитать вывод до конца**, не только первую строку.
3. **Сначала проверить частые ложные следы Пульта:**
   - пояснение не то - чаще это данные `knowledge/*.json`, а не код;
     `node knowledge/validate.mjs` и сам JSON раньше `explain.rs`;
   - окно и терминал ведут себя по-разному - логика утекла из `core` в
     оболочку (правило 3);
   - git «не видит» репозиторий - `.git/config` с `core.hooksPath` или
     `fsmonitor` делает его недоверенным (`git.rs`, `security.md`), это
     защита, а не баг;
   - окно пустое или старое - тестовое окно собрано из другой папки сборки
     или открыто на чужом порту (`tools/test-window.ps1 -Port`);
   - только Windows - Job Object, `PATHEXT`, кодировка вывода (`encoding_rs`).
4. **Гипотеза одним предложением**, проверка точечно (`dbg!`, временный
   `console.log` - убрать до коммита). Не подтвердилась - новая гипотеза, а
   не заплатка поверх старой.
5. **После подтверждённой причины** - минимальный фикс и тест, который
   падает на старом коде и проходит на новом.

## Формат ответа

Первопричина (одно предложение) -> как проверено (команда и вывод) ->
минимальный фикс -> тест, который её ловит.
